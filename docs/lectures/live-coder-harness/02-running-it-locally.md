# 第2回 ローカルで動かしてみる

副題: まずは自分の手で、入口を開けるようになる

## この回の位置づけ

第1回では、このスターターがアプリ本体と作業ルールをセットで持つ環境だと確認しました。

第2回では、その環境を実際に自分の手で起動し、どこが入口で、何を順番に確認すればよいのかを体で覚えます。

## 対象

- エンジニアではないライブコーダー
- ターミナル操作にまだ慣れていない人
- まずは動かすところまで自力でたどり着きたい人

## この回のゴール

- ローカルでアプリを起動するための最小手順を説明できる
- `npm install`、`db:prepare`、`npm run dev` の役割をざっくり理解する
- ブラウザでどこを見れば起動確認になるか分かる
- 「エラーが出ても終わりではなく、確認ポイントがある」と理解する

## この回で伝えたい中心メッセージ

- 最初に目指すのは、完璧に理解することではなく、起動の流れを再現できることです
- ローカル起動は、今後のすべての講義の土台です
- つまずいた時は、コードを疑う前に順番と入口を確認します

## 導入で使う一言

> 今回の目標は、コードを読むことではありません。  
> 自分の手で起動して、「この環境はちゃんと動く」と確認できることです。

## 1. ローカルで動かすとは何か

### 伝えること

- ローカルとは、自分のPCの中で動かすこと
- まだ公開も共有もしない、練習と確認のための場所
- ここで動かせると、試す、壊す、戻すがやりやすくなる

### 話す例

- いきなり本番で試すのではなく、まず机の上で動かすイメージです
- ライブコーディングでは、この「すぐ試せる」がかなり大事です

## 2. 起動までの最小手順

### まず伝えること

- 最初から全部の意味を理解しなくてよい
- この回では、次の順番だけ覚えれば十分

```bash
cp .env.example .env
npm install
npm run db:prepare
npm run dev
```

### それぞれの役割をやさしく説明する

#### `cp .env.example .env`

- 起動に必要な設定のひな形を、実際に使う設定ファイルへコピーする
- 中身を今すぐ全部理解する必要はない

#### `npm install`

- このプロジェクトが必要とする道具をまとめて入れる
- 料理でいうと、使う器具や材料をそろえる段階

#### `npm run db:prepare`

- ローカルのデータベースを使える状態に整える
- このスターターでは PostgreSQL を使う
- 必要な初期データもここで入る

#### `npm run dev`

- 開発用のアプリを起動する
- ブラウザで見に行けるようになる

### 講師の実演ポイント

- 1行ずつ実行して、何が起きているかを短く説明する
- 長いログは全部読まなくてよいと先に伝える
- 大事なのは「成功したか」「次に何をするか」の2点だと示す

## 3. ブラウザでどこを確認するか

### 起動後に確認する場所

- トップページ
- `/events`
- `/login`
- `/dashboard`

### この回での見方

- ページが開くか
- 画面が大きく崩れていないか
- ログイン前にダッシュボードへ行くと、ログインへ案内されるか

### ここで伝えること

- 今は見た目の細かい良し悪しは追わない
- まずは「入口が生きているか」を確認する

## 4. よくあるつまずき方

### 先に伝えておくと安心なこと

- エラーが出ても珍しくない
- 失敗した時は、順番に確認すればよい
- いきなりコード修正に行かない

### よくある確認ポイント

- `npm install` が終わっているか
- `db:prepare` が通っているか
- `.env` があるか
- PostgreSQL 用のローカル環境が起動しているか
- すでに同じポートで別のアプリが動いていないか

### 講師が使える一言

- エラーが出たら失敗ではなく、確認ポイントが1つ増えただけです
- まずは何を直すかではなく、どこで止まったかを見ます

- ローカル起動は今後の学びの土台になる
- つまずいた時は、まず入口と順番を確認する
