# 第6回 動かして確かめるチェック

副題: Vitest、Playwright、verify:all は何を見ているのか

## この回の位置づけ

第5回では、`Prettier`、`ESLint`、`Typecheck` を使って、見えないミスを早めに止める考え方を学びました。

第6回では、今度は「実際に動かして確かめる」ための道具を扱います。

この回の主役は `Vitest`、`Playwright`、`verify:all` ですが、難しいテスト理論を覚えることが目的ではありません。
それぞれが、どの範囲を、どの深さで見ているのかを区別できるようになることが目的です。

## 対象

- エンジニアではないライブコーダー
- チェック系コマンドが多くて違いが見えにくい人
- 「動くかどうかをどう確かめるのか」を整理したい人

## この回のゴール

- `Vitest`、`Playwright`、`verify:all` の違いをざっくり説明できる
- 「書き方を見るチェック」と「動きを見るチェック」は別だと理解する
- どの確認を軽く回し、どの確認を最後にまとめて回すかイメージできる
- テストを怖いものではなく、確認の段取りだと捉えられる

## この回で伝えたい中心メッセージ

- テストは、失敗させるための仕組みではなく、安心して進むための確認です
- すべてを毎回同じ重さで回すのではなく、目的に応じて使い分けます
- `verify:all` は 1 つの道具ではなく、最終点検のまとめ入口です

## 1. なぜ動かして確かめる必要があるのか

### 伝えること

- 書き方がきれいでも、実際の動きが意図どおりとは限らない
- 見た目が合っていても、押した後の流れが崩れていることがある
- だから、実際に動くかどうかを別で確かめる必要がある

### 話す例

- 説明書どおりに組み立てても、スイッチを入れたら動かないことがあります
- UI も同じで、書き方と実際の動きは別に確認した方が安全です

## 2. Vitest は何を見るのか

### やさしい説明

- 小さめの単位で動きを確かめる道具
- 部品やロジックが、期待どおりに反応するかを見る
- 比較的軽く、早く回しやすい

### この回での言い方

- 小さい確認
- 部品やロジックの動作確認

### 実演コマンド

```bash
npm run test
```

### ここで伝えること

- 画面全部を見るわけではない
- でも、小さい単位の崩れを早めに見つけやすい
- 「ここを変えたら、この部分は大丈夫か」を確かめる時に向いている

## 3. Playwright は何を見るのか

### やさしい説明

- ブラウザを使って、実際の画面操作に近い流れを確かめる道具
- クリック、移動、表示、遷移といった流れをまとめて見る

### この回での言い方

- 画面を歩くテスター
- 実際の操作に近い確認

### 実演コマンド

```bash
npm run test:e2e
```

### ここで伝えること

- 小さい部品だけではなく、画面から画面への流れを見る
- 本番に近い確認ができるぶん、Vitest より重いことが多い
- 「この操作の流れは最後まで通るか」を確かめる時に向いている

## 4. verify:all は何をまとめているのか

### やさしい説明

- いろいろな確認をまとめて順番に回す入口
- 1つのテストではなく、総点検に近い

### 実演コマンド

```bash
npm run verify:all
```

### この回で伝えること

- `verify:all` は「最後にまとめて確認する」ための入口
- 中では format、lint、typecheck、test、storybook、e2e などが順に実行される
- 普段の細かい確認とは別に、区切りで回す意味がある

### この回での言い方

- 最終点検
- 出発前の総チェック

## 5. どう使い分けるか

### シンプルな整理

- `test`: 小さめの動作確認
- `test:e2e`: 画面全体の流れ確認
- `verify:all`: 最後にまとめて確認

### 前回とのつながり

- `format:check`、`lint`、`typecheck`: 書き方や受け渡しを見る
- `test`、`test:e2e`: 実際の動きを見る
- `verify:all`: それらをまとめて確認する

### 講師が言える一言

- 毎回フルコースで確認する必要はありません
- 軽い確認と重い確認を分けると、作業が続けやすくなります
