# 第13回 品質を見える形で追い続ける

副題: quality score、debt tracker、cleanup は何を守っているのか

## この回の位置づけ

第12回では、review suite を使って、変更をどこで止めるかという gate の考え方を整理しました。

第13回では、その gate を一度通したあとも、品質を見える形で追い続けるための仕組みを扱います。

この回の主役は `quality score`、`tech debt tracker`、`cleanup:check` ですが、管理表を読むだけの回ではありません。
良い状態を保つには、「見えること」「残すこと」「掃除すること」が必要だと理解する回です。

## 対象

- エンジニアではないライブコーダー
- 品質管理という言葉がまだ抽象的に感じる人
- 良い状態をどう保ち続けるのかを知りたい人

## この回のゴール

- quality score が何のためにあるか説明できる
- tech debt tracker が何を残しているか説明できる
- `cleanup:check` が何を防いでいるか説明できる
- 品質は「気合い」ではなく「見える運用」で保つものだと理解する

## この回で伝えたい中心メッセージ

- 品質は、1回よく作れば終わりではありません
- 時間がたつと、docs も生成物も運用も少しずつずれていきます
- だから、品質を数字や一覧で見えるようにし、不要なものを片づける仕組みが必要です

## 導入で使う一言

> 壊れる瞬間だけを見るのではなく、少しずつ悪くなる流れも見えるようにしたいです。  
> 今日は、そのための見える運用を整理します。

## 1. なぜ品質を見える化する必要があるのか

### 伝えること

- 品質が落ちても、すぐには壊れないことがある
- そのまま放置すると、後で大きな崩れ方をしやすい
- だから、悪化を早めに見つける仕組みが必要になる

### 話す例

- 部屋は一気に散らかるのではなく、少しずつ散らかります
- コードや運用も同じで、見えないまま進むと後で大変になります

## 2. quality score は何をしているのか

### やさしい説明

- 今この環境が、どこまで整っているかを見えるようにする表
- 何が強くて、何がまだ弱いかを一覧で確認できる

### この回での言い方

- 品質の見取り図
- 今の強さを見える化する表

### この環境での見方

- `0`: まだない
- `1`: 書いてあるだけ
- `2`: 一部できている
- `3`: 実装され、守られている

### ここで伝えること

- quality score は自慢のためだけにあるのではない
- どこが未成熟かを隠さずに見るためにある
- たとえばこの環境では review automation は `2` で、まだ伸びしろがある

## 3. tech debt tracker は何をしているのか

### やさしい説明

- 「今はまだ残っている課題」を忘れないための一覧
- 思い出した時だけ話すのではなく、見える場所に残しておく

### この回での言い方

- 未完了の課題リスト
- 借りを見える場所に置く表

### ここで伝えること

- debt はゼロである必要はない
- でも、見えない debt は扱いにくい
- open の理由と、閉じる条件が分かる形にしておくのが大事

### 講師が言える一言

- 問題があることより、問題が見えないことの方が危ないです

## 4. cleanup:check は何をしているのか

### やさしい説明

- repo の中に、不要なものやずれたものが増えていないかを見る
- 「あとで消せばいい」を積み上げないための確認

### 実演コマンド

```bash
npm run cleanup:check
```

### この環境で見ていること

- 必要な docs が欠けていないか
- 追跡すべきでない生成物や sample asset が戻ってきていないか
- cleanup drift が増えていないか

### この回での言い方

- repo の掃除チェック
- 片づけ忘れを見つける入口

### ここで伝えること

- cleanup は見た目の美しさだけではない
- 余計な生成物や古いファイルが混ざると、何が正しいのか分かりにくくなる
- docs の不足も drift の一種として扱う

## 5. この3つを一緒に持つ意味

### シンプルな整理

- quality score: 今どこまで整っているかを見る
- tech debt tracker: 何がまだ残っているかを見る
- cleanup:check: 不要なずれが増えていないかを見る

### ここで伝えること

- quality score だけだと、細かい未完了がぼやける
- debt tracker だけだと、全体の現在地が見えにくい
- cleanup だけだと、運用の方向性までは分からない
- だから 3 つをセットで持つと強い

### 講師が言える一言

- 「今どこにいるか」「何が残っているか」「何が散らかっているか」を分けて見るのが大事です
