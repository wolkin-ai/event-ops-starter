# 第4回 Storybookで部品を1つずつ見る

副題: アプリ全体ではなく、画面の部品を見る練習

## この回の位置づけ

第3回では、公開画面と管理画面を「誰のための画面か」という役割で読み分けました。

第4回では、アプリ全体をまとめて見るのではなく、画面を作っている部品を1つずつ見る方法に進みます。

この回で扱う Storybook は、実装のための難しい道具としてではなく、確認しやすくするための場所として捉えます。

## 対象

- エンジニアではないバイブコーダー
- アプリ全体を見ていると何が変わったのか追いにくい人
- UI を少しずつ安全に確認したい人

## この回のゴール

- Storybook が何のための道具かを説明できる
- アプリ全体を見ることと、部品だけを見ることの違いを理解する
- Storybook を開いて、いくつかの部品を見比べられる
- 今後 UI 変更を学ぶ時の確認場所を先に持てる

## この章の中心メッセージ

- アプリ全体だけを見ていると、どこが変わったのか分かりにくい
- 部品を1つずつ見ると、変化や違和感に気づきやすい
- Storybook は、部品のカタログであり、試着室であり、確認場所でもある

## 導入のひとこと

> 今日はアプリを全部まとめて見るのを少しやめて、部品だけを見ます。  
> そうすると、どこを直したのか、何が変わったのかがかなり分かりやすくなります。

## セクション構成案

1. なぜ部品ごとに見るのか
2. Storybook は何をする場所か
3. 実際に Storybook を開いてみる
4. どんな見方をすればよいか
5. 次回へのつながり

## 1. なぜ部品ごとに見るのか

### 押さえるポイント

- アプリ全体を毎回見ていると、変化した場所を見失いやすい
- 小さな部品に分けて見ると、違いに気づきやすい
- 1つの部品だけなら、関係ないものに引っ張られずに確認できる

### 身近なたとえ

- 家全体を見るより、椅子だけ見た方が色や形の違いに気づきやすい
- 画面も同じで、全体より部品単位の方が確認しやすいことが多い

## 2. Storybook は何をする場所か

### やさしい説明

- 画面の部品を1つずつ並べて見られる場所
- いろいろな状態を比べられる場所
- 本体アプリを開かなくても確認できる場所

### この回での言い方

- 部品のカタログ
- 部品の試着室
- UI の確認場所

### ここで整理すること

- Storybook は完成アプリの代わりではない
- でも、部品を確認するにはかなり便利
- 後で UI を直す時に、最初に見る場所になりやすい

## 3. 実際に Storybook を開いてみる

### 実行するコマンド

```bash
npm run storybook
```

### 画面で確認すること

- 左側に部品の一覧があること
- 1つ選ぶと、その部品だけが表示されること
- 同じ部品でも、状態違いを見られること

### ここで意識する読み方

- アプリ本体では、周りの画面も一緒に見えてしまう
- Storybook では、その部品だけを集中して見られる

## 4. どんな見方をすればよいか

### この章での見方

- 何の部品か
- どんな場面で使う部品か
- 正常そうに見えるか
- 状態違いがあるか
- 触った時に変な挙動がないか

### 見る時の観点

- 文字は読めるか
- ボタンは押せそうか
- 情報の順番は分かりやすいか
- エラーっぽい状態や空っぽの状態もあるか

### ここで伝えたいこと

- まだコードを読めなくても、UI の違和感は見つけられる
- Storybook は「実装者だけの道具」ではなく、「確認する人の道具」でもある

## 5. 次回へのつながり

### 次回予告

- 第5回では、ESLint、Prettier、Typecheck のような「見えないチェック」の話に入る

## おすすめの進め方

1. アプリ本体を少し見る
2. Storybook を開く
3. 部品一覧を見る
4. 1つの部品を選ぶ
5. 状態違いを見比べる
6. アプリ本体で見るのと何が違うか言葉にする

## 進めながら頭に置く一句

- ここでは部品だけを見るので、何が変わったか追いやすいです
- アプリ全体が重い時でも、部品だけなら見やすいことがあります
- まず Storybook で確認してから、本体アプリで見る流れはかなり強いです

## 受講者にやってもらう最小課題

- `npm run storybook` を実行する
- 部品を 2 つ以上開く
- 同じ部品の状態違いを 1 組見つける
- アプリ本体で見る時との違いを一言で言う

## 受講後に残したい理解

- Storybook は画面全体ではなく部品を見る場所
- 部品単位で見ると、違和感や変化に気づきやすい
- UI を安全に触るための確認場所として役立つ
- 次回は見た目ではなく、書き方やミスを止めるチェックへ進む

## 締めのひとこと

> 今日は、アプリ全体ではなく部品を見るやり方を学びました。  
> 次回は、見た目では分からないミスを早めに止めるためのチェック道具に進みます。
