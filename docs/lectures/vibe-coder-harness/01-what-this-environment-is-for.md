# 第1回 この環境は何のためにあるのか

副題: アプリを作る前に、壊れにくい作業場を知る

## この回の位置づけ

この回は、設計用語を覚える回ではありません。

このスターターが「ただのサンプルアプリ」ではなく、アプリ本体と安全に作業する仕組みをセットで持つ環境だと理解するための導入回です。

## 対象

- エンジニアではないバイブコーダー
- コードより先に全体像を知りたい人
- 今後の講義で使う道具の役割を先に知っておきたい人

## この回のゴール

- このスターターが何を守るための環境かを説明できる
- 公開画面と管理画面の両方が入っている意味を理解する
- 「機能を作ること」と「安全に作り続けること」は別だと理解する
- 今後の講義で扱う道具の全体像をざっくりつかむ

## この回で伝えたい中心メッセージ

- この環境の主役は機能だけではなく、安全に作る仕組みです
- ハーネスエンジニアリングは、人やAIが何度作業しても壊れにくくするための考え方です
- 今日は用語の暗記ではなく、地図を手に入れることが目的です

## 導入で使う一言

> この講座は、いきなりコードを書く講座ではありません。  
> まず、安心して試せて、壊しても戻せて、何を見ればよいか分かる「作業場」を理解するところから始めます。

## セクション構成案

1. なぜ環境から始めるのか
2. このスターターには何が入っているか
3. ハーネスエンジニアリングをやさしく言うと何か
4. 実際に画面を見てみる
5. 今後の17回はどうつながるか

## 1. なぜ環境から始めるのか

### 伝えること

- バイブコーディングでは、うまくいく瞬間より崩れた時に差が出る
- 何が壊れたのか分からない状態が一番つらい
- だから先に、確認しやすい環境、戻しやすい環境、迷いにくい環境を用意する

### 話す例

- コードが書けることと、作業が続けられることは別です
- 今日のテーマは機能開発ではなく、安心して作れる土台です

## 2. このスターターには何が入っているか

### 伝えること

- 公開向け画面がある
- 管理向け画面がある
- ローカルで動かせる
- UI を部品ごとに確認できる
- テストやチェックの入口がある
- AI に守らせるルールが repo の中に入っている

### この場で見せるもの

- public flow
- admin flow
- Storybook
- verify 系コマンド
- docs 群

## 3. ハーネスエンジニアリングをやさしく言うと何か

### 伝え方

- 車でいうシートベルトや計器盤のようなもの
- 作ることそのものではなく、安全に作り続けるための仕組み
- 人やAIが同じ場所で迷わず動くためのガイドと点検装置

### この回ではこの3点だけで十分

- 迷わない
- 壊れても気づける
- 同じやり方を繰り返せる

## 4. 実際に画面を見てみる

### 見せる順番

1. トップページ
2. イベント一覧
3. ログイン画面
4. ダッシュボード
5. 管理画面
6. Storybook

### この時に添える説明

- アプリ全体を見る場所がある
- 部品だけを見る場所がある
- 確認用の入口が分かれている
- 全部を一気に理解しなくてよい
