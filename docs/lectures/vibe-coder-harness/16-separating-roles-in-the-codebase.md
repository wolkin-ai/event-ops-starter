# 第16回 役割を混ぜない設計

副題: Clean Architecture を「置き場所のルール」として理解する

## この回の位置づけ

第15回では、外部サービスを安全に足すための確認順序と continuity を整理しました。

第16回では、ここまで後回しにしてきた「役割を混ぜない設計」に入ります。

この回の主役は `Clean Architecture` と `Domain <- Application <- Infrastructure <- Interface/UI` ですが、設計理論を暗記する回ではありません。
「何をどこに置くと、後で混乱が減るか」をつかむ回です。

## 対象

- エンジニアではないバイブコーダー
- フォルダや層の話になると急に難しく感じる人
- 画面、ロジック、外部接続が混ざると何が困るのかを知りたい人

## この回のゴール

- 役割を混ぜない方がよい理由を説明できる
- `Domain`、`Application`、`Infrastructure`、`Interface/UI` をやさしく言い換えられる
- 「見た目」「判断」「外部接続」を分ける感覚を持てる
- `依存方向を固定する` ことがなぜ大事かをざっくり理解する

## この回で伝えたい中心メッセージ

- 設計が難しくなる一番の理由の1つは、役割が混ざることです
- 見た目の話、判断の話、外部接続の話を分けると、変更しやすくなります
- Clean Architecture は、難しい理論というより「混ぜないための配置ルール」として見ると分かりやすいです

## 1. なぜ役割が混ざると困るのか

### 伝えること

- 画面の見た目と、業務ルールと、外部接続が同じ場所にあると変更しにくい
- どこを直したらよいか分かりにくくなる
- 1か所を触ったつもりで、別の役割まで壊しやすくなる

### 話す例

- 台本、照明、音響、出演順のメモが全部1枚の紙に混ざっていたら運用しにくいです
- コードも同じで、役割を分けると追いやすくなります

## 2. 4つの置き場所をやさしく見る

### Domain

- そのアプリで本当に大事なルールや意味を置く場所
- この回での言い方: 中心ルール

### Application

- そのルールを使って、何をするかを組み立てる場所
- この回での言い方: 進め方の組み立て

### Infrastructure

- DB や外部サービスや保存のしかたに近い場所
- この回での言い方: 外の仕組みとのつなぎ

### Interface/UI

- 画面や route など、外から触る入口に近い場所
- この回での言い方: 見える入口

### ここで伝えること

- 4つを完璧に定義できなくてもよい
- まずは「中心ルール」「進め方」「外部接続」「見える入口」が分かれれば十分

## 3. 依存方向を固定するとは何か

### この環境の基本形

```text
Domain <- Application <- Infrastructure <- Interface/UI
```

### やさしい説明

- 外側は内側を使う
- でも、内側は外側の細かい都合を知らない方がよい

### この回での言い方

- 中心に近いものほど、外の都合に引っ張られにくくする
- 外側から内側へ頼る形をそろえる

### ここで伝えること

- Domain が UI の見た目都合を知らない方が楽
- Application が DB の細かい都合を知らない方が楽
- そうすると、外側を変えても中心ルールが崩れにくい

## 4. この環境ではどう分けているか

### この環境の大きな分かれ方

- `src/features/*/domain`
- `src/features/*/application`
- `src/features/*/infrastructure`
- `src/app` や `src/components`

### この回で伝えること

- `catalog`
- `registration`
- `admin-events`
- `session`

こうした slice ごとに、同じ分け方を繰り返している

### 講師が言える一言

- 1回きりの分け方ではなく、slice ごとに同じ考え方を繰り返すのが大事です

## 5. UI / Logic / I/O を分ける意味

### この環境での整理

- UI: 見た目
- Logic: 状態や判断
- I/O: 外とのやり取り

### やさしい説明

- 見た目の修正をしたいのに、外部接続まで混ざっていると扱いにくい
- 逆に、保存先を変えたいのに画面の都合まで引きずると扱いにくい
- 分けておくと、変えたい場所だけを見やすくなる

### 講師が言える一言

- 「見せる」「考える」「つなぐ」を分けるだけでも、かなり整理されます
